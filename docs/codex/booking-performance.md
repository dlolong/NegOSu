# Booking and hospitality loading improvements

Appointment creation now loads visit choices and promos concurrently. Pet-care appointment promos join the existing parallel data load. Apartelle booking dialogs load the room list, selected room, branch timezone and staff directory concurrently. Stay/checkout pages load independent branch, staff, extension and bill-link data together, then load the current invoice and deposit together. Charge/payment history is only requested for the Charges tab or payment-reversal dialog, rather than for every dialog.

Searchable dropdowns reuse successful searches for 30 seconds, including empty results, with a maximum of 20 queries per mounted control. The cache is memory-only, not localStorage or a shared server cache. Dashboard scope includes the user, business, branch and role; switching scope remounts controls. Changed supplied choices (including inline creation), lookup kind or linked customer scope replaces the control cache. Unmount discards it. Failed requests are not cached, and canceled responses are ignored. Controls outside the authenticated scope provider retain uncached behavior.

Already-loaded staff, resource, promo and room-rate choices continue to filter locally. No server-wide caching of private catalog data was introduced. Availability, permissions, balance, refundable deposits, prices and final check-in/checkout/payment writes remain authoritative in existing authenticated database calls. No migration, RPC, RLS, credit cost, transaction lock or idempotency behavior changed. Existing branch and shift defaults remain in place. Standard Next Link prefetch behavior is retained.

Validation: 651 unit tests passed, including TTL expiry, empty result reuse, bounded memory and isolated caches. Lint, typecheck and the Webpack production build passed. Browser fixture verification checks that reopening a lookup uses one request, while new choices and switching businesses request fresh results. Live hospitality tests require configured test credentials and were skipped; no hosted benchmark or production data was used. Expected benefit is fewer sequential database waits and repeated lookup requests, not a claimed measured latency improvement. A next staging check is to compare form-opening and save timings on the same connection while exercising concurrent arrivals and checkout/deposit returns.

Final browser run: 18 cache/form regression tests passed. The form regression selector was corrected to inspect only open dialogs; a closed auxiliary service dialog had caused a false failure. Thirteen authenticated hospitality browser tests were skipped because their test-login configuration was unavailable. Self-review found no changes to write authorization or transactional behavior. Database-backed and real-network timing checks remain outstanding.

## Payments layout follow-up

Payments now uses a shared `PaymentsLayout` with the Reports page hierarchy: header, full-width tabs, right-aligned toolbar, summary cards and table. Core Payments keeps Outstanding/History, its server-side search and pagination, currency-aware collection totals and transaction links. Apartelle keeps Outstanding/Collections/Deposits/Stays, existing date filters and scope, with an expandable search beside the filter icon that searches loaded rows. Payment-method breakdowns remain available below the table. No payment query, calculation, permission, credit cost, database migration or write path changed.

Validation: full unit suite (651 tests), lint, typecheck and Webpack production build passed. Browser fixture tests cover hidden filters, applying dates and retaining the section, keyboard/outside dismissal, popup positioning and mobile/desktop tab-toolbar-summary-table order plus expandable search. Updated an obsolete test selector from the former summary toggle to the existing filter button. No production deployment or live account changes were performed.

Payments scope refinement: core History is now labeled Collections while retaining its existing URL/query contract. Apartelle Payments offers only Outstanding, Collections and Deposits; old `section=stays` links redirect to Bookings history with their date/page filters. Payments has a permission-gated Reports & exports link, while summaries/CSV remain in the reporting workspace. Existing operational collection cards and new-sale/bill links remain available. The hospitality all-bills workspace now correctly links to Bookings instead of automotive appointments. No financial calculation or authorization was changed. Targeted payment-view and hospitality-reporting tests passed (16); typecheck and targeted lint passed. Live authenticated navigation was not exercised for this small navigation change.
