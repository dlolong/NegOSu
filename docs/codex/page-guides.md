# Dashboard and checkout guides

Driver.js 1.8.0 provides optional tours for Dashboard (including Pet Care), New Product Sale, Checkout, and Payment. A compact help icon beside notifications in the dashboard header starts the guide and remains available for replay. It has an accessible label and tooltip; there is no first-use banner or extra content row. On the first visit to each supported page, the tour starts automatically after visible targets are ready. It waits while an edit dialog is open, the tab is hidden, or a form field is focused. Started, completed or dismissed tours do not automatically restart in this browser; the icon always allows replay. Receipt printing and unrelated pages have no guide controls.

Steps use existing semantic IDs and include only visible elements, respecting the role-specific page controls. Hospitality receives check-in wording. Tours explain controls without advancing routes, submitting forms or changing business data. Open native dialogs prevent a tour from starting; opening one during a tour destroys the tour. Route/membership/role changes also clean up overlays. Skip, Escape, Back, Next and Done are available. Focus returns to Guide after dismissal. Reduced-motion preferences disable tour animation.

Completion/dismissal is stored locally under `negosu:guide:v1:<membership>:<industry>:<role>:<guide>`. It is browser-specific, not synchronized across devices, and contains no customer or transaction data. Unavailable local storage does not block manual guides. Increment the version when onboarding content materially changes.

The engine is dynamically imported when the guide starts, automatically on first use or when its icon is clicked. Its CSS is imported globally so popovers are styled immediately. Installed distribution measurements: JavaScript 7,195 gzip bytes; CSS 972 gzip bytes. These are package-file measurements, not the final application chunk size. No database changes or new external services are required.

Validation: three focused unit tests cover route selection, persistence isolation, bounded tours and stock/payment wording. Four browser cases passed across desktop and 375px mobile: completion, replay, optional dismissal, focus return, viewport containment, no sale mutation, native-dialog cleanup, and component-unmount cleanup. These use the actual guide component with synthetic page controls, not authenticated production data.

Dependency audit: Driver.js has no reported advisory in the audit performed for this change. Existing dependencies report a critical Next.js advisory (GHSA-vcvr-r3jv-pc5j, next/og ImageResponse) and high brace-expansion advisories. These predate Driver.js and are OUT OF SCOPE for this UI feature; resolve them in a dedicated dependency update before production release. No claim of exploitability assessment is made here.

First-use update: auto-start waits for visible targets and defers to native dialogs, form focus and hidden tabs. Four of six browser cases passed; two caught immediate Escape closing during Driver's initial animation before its onDestroyed hook runs. Dismissal is now saved in onDestroyStarted, before teardown. The final browser rerun was declined, so this last correction has not been browser-verified. Targeted lint and TypeScript checks passed.
