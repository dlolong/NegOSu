# Safe record removal

The Remove action covers Products, Promos, Staff, Rooms, Services and Scheduling Resources. Existing category deletion is unchanged. Controls are shown only within existing-record edit pages/dialogs, below the save form. Successful removal returns to the listing with a result message. Each control requires confirmation, prevents duplicate submits, and reports a safe error or the deletion/archive outcome.

Apply migrations through **0113_safe_record_removal.sql** in order. No hosted migration was applied. The migration exposes one authenticated allowlisted RPC and preserves existing RLS and write grants. The RPC verifies organization, current branch and owner/manager role; staff additionally requires staff management permission. Organization-wide staff and service changes require access to every active branch. Owners and the actor's own staff profile are protected. Occupied rooms cannot be removed.

The RPC locks the target record and checks every inbound foreign key (including cascading relationships and composite keys), plus JSON promo component references. A record with any such reference is archived instead of deleted. This deliberately includes configuration dependencies as well as transaction history. Product/service removal locks promo writes while checking JSON references. Staff archiving deactivates linked membership and revokes pending invitations. All removals are audited. Archived records remain visible in management lists for inspection/reactivation, and existing active-only selectors omit them. Staff login reactivation remains a separate access-management action.

Scope excludes financial documents, customers, appointments, booking requests and historic transactions. Their existing workflow actions are unchanged. No accounting or stock ledger is deleted by this feature.
